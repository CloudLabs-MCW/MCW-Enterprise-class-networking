## Exercise 10: Using Network Watcher to Test and Validate Connectivity

### Estimated Duration: 60 Minutes

## Lab Overview

In this exercise, you will use Azure Network Watcher to capture logs, review traffic, and troubleshoot connectivity between your on-premises and Azure environments. You will configure flow logs, enable diagnostics, analyze traffic patterns, and test connections to ensure everything works as expected.

## Lab objectives

In this lab, you will perform the following tasks:

- Task 1: Configuring the Storage Account for the NSG Flow Logs
- Task 2: Configuring Diagnostic Logs
- Task 3: Reviewing Network Traffic
- Task 4: Network Connection Troubleshooting

### Task 2: Configuring Diagnostic Logs

In this task, you will enable diagnostic logs on network resources (like NSGs) to track traffic, events, and alerts. Logs are sent to Log Analytics Workspace and storage for monitoring.

1. In the search bar of the Azure portal, type **Network watcher (1)**. From the search results, select **Network Watcher (2)**.

   ![](images/clsse-image65.png)

1. From the left navigation pane expand **Logs (1)**, then choose **Diagnostic Logs (2)**, and select **OnPremVM-nsg (3)**.

     ![](images/clsse-image70.png)

1. Click **+ Add Diagnostic Setting**.

1. Enter **OnPremDiag (1)** as the Diagnostic setting name, select **All logs (2)**, enable **Send to Log Analytics workspace (3)**, and choose the previously created workspace. 

1. Check **Archive to a storage account (4)**, select the available storage account, and click **Save (5)** to apply the settings.

     ![](images/02032025(8).png)

   > **Note** : Please repeat the above steps for adding diagnostics logs for **WGAppNSG1**.
   
   > **Note** : You can enable diagnostic logging for all network resources if required, following the same steps outlined above for now continue with below task.

### Task 4: Network Connection Troubleshooting

In this task, you will run connection troubleshooting tests in Network Watcher to simulate and validate connectivity between virtual machines (e.g., OnPremVM to WGWEB1). This helps identify routing issues or blocked ports.

1. In the search bar of the Azure portal, type **Network watcher (1)**. From the search results, select **Network Watcher (2)**.

   ![](images/clsse-image65.png)

1. Select **Connection Troubleshoot (2)** from the **Network Diagnostic tools (1)** menu.

   ![](images/clsse-image66.png)

1. To troubleshoot a connection or to validate the route, enter the following information and select **Run diagnostic tests (9)**:

    | Setting | Action |
    | -- | -- |
    | Source Type | **Virtual Machine (1)** |
    | Virtual Machine | **OnPremVM (2)** |
    | Destination | **Select a virtual machine (3)** |
    | Virtual Machine | **WGWEB1 (4)** |
    | Preferred IP version | **IPV4 (5)** |
    | Protocol | **TCP (6)** |
    | Destination Port | **80 (7)** |
    | Diagnostic tests | **Next hop (8)** |

   ![](images/clsse-image67.png)
   
   ![](images/clsse-image68.png)

1. Once the diagnostic tests have completed, the results will be displayed.

    ![](images/clsse-image69.png)

     >**Note**: Sometimes, running the diagnostic tests may take longer, so the results may not appear immediately as shown in the screenshot.
